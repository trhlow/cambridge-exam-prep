## Commands

Run from `src/backend` unless noted. Requires .NET SDK 10 (pinned in `global.json`) and Docker Desktop.

```bash
# Start MySQL only (from repo root). docker/.env holds the passwords and is git-ignored; copy docker/.env.example first.
docker compose -f docker/docker-compose.yml --env-file docker/.env up -d mysql
# Or the whole system (MySQL + API + nginx serving the built frontend and proxying /api) at http://localhost:8080.
# The api container runs as Development (demo exam), migrates on start (Database:MigrateOnStart) and shares the
# MySQL volume and src/backend/src/ExamPrep.Api/App_Data with `dotnet run`.
docker compose -f docker/docker-compose.yml --env-file docker/.env up -d --build

# Connection string for the API (Development reads user-secrets)
dotnet user-secrets set "ConnectionStrings:ExamPrep" "server=localhost;port=3306;database=examprep;user=examprep;password=<MYSQL_PASSWORD>" --project src/ExamPrep.Api

# Build / run (health check at /health)
dotnet build
ASPNETCORE_ENVIRONMENT=Development dotnet run --project src/ExamPrep.Api

# Migrations (design-time factory reads ConnectionStrings__ExamPrep from the environment)
dotnet ef migrations add <Name> -p src/ExamPrep.Infrastructure -s src/ExamPrep.Api -o Persistence/Migrations
ConnectionStrings__ExamPrep="<conn>" dotnet ef database update -p src/ExamPrep.Infrastructure -s src/ExamPrep.Api

# Tests (Microsoft.Testing.Platform runner, xUnit v3). DB tests need a server-level root connection
# and are reported as skipped without it; each run creates and drops its own examprep_test_* database
# (migrations run one at a time on an unpooled connection: EF's MySQL migration lock is server-wide).
EXAMPREP_TEST_MYSQL="server=localhost;port=3306;user=root;password=<MYSQL_ROOT_PASSWORD>" dotnet test
dotnet test --filter-method "*SnakeCase*"      # single test / pattern
```

## Backend architecture (`src/backend`)

- `ExamPrep.Domain` — entities (one class per file), enums, and domain logic: `Delivery/AttemptClock` (all timer and audio rules; throws `Common/DomainRuleException` for operations not allowed in the current state). No EF dependency.
- `ExamPrep.Infrastructure` — `Persistence/ExamPrepDbContext`, one `IEntityTypeConfiguration` per entity in `Persistence/Configurations`, migrations, `SeedData` (exam types, section templates, default branding "Victory"). `ModelConventions` stores every enum as `varchar(32)` text and every `DateTime` as UTC; `SnakeCaseNaming` lower-snake-cases all tables and columns. Provider is Oracle's `MySql.EntityFrameworkCore` 10 (`UseMySQL`), because Pomelo has no EF Core 10 release.
- `ExamPrep.Api` — ASP.NET Core host; `AddInfrastructure` fails fast if the connection string is missing. `Auth/` has two separate cookie schemes sharing `ApiCookieOptions` (HttpOnly, SameSite=Strict, 401/403 instead of redirects): **Staff** (`victory.staff`, roles Admin / Manager / Examiner / Invigilator, an `area` claim per manager area; policies `Staff`, `Admin`, `Papers`/`Exams`/`Candidates`/`Centre` (admin or a manager of that area), `CandidateList`, `Results` (admin or examiner), `Examiner`; first admin from `Bootstrap:AdminUsername`/`AdminPassword`) and **Candidate** (`victory.candidate`; login → `pin_verified=False`, `POST /api/candidate/auth/pin` re-issues it with `True`; policy `CandidateExam` requires the PIN). Both re-check `security_stamp` on every request; candidate login rotates it. Candidates can sign in only while `exams.status = Active`. `LoginThrottle` locks an account for 5 minutes after 10 wrong passwords (or 10 wrong PINs for a candidate), counted per account id because MySQL matches usernames ignoring case and accents. Data Protection keys (cookies, re-printable candidate passwords) persist in `App_Data/keys` (`DataProtection:KeysPath`). Every response carries nosniff / X-Frame-Options DENY / no-referrer / CSP `default-src 'none'`; outside Development a ProblemDetails exception handler and HSTS.
- `ExamPrep.Infrastructure/Content` — exam packages (one .zip per paper: `paper.json` + images/ + audio/, spec in `setup/exam-package/FORMAT.md`): `PaperPackageReader` (strict JSON, names confined to the package, size limits) → `PaperPackageValidator` (template part count, numbering 1..N, per-interaction rules; returns every error as an admin-readable sentence) → `PaperPackageImporter` (SHA-256 content-addressed `IAssetStorage` under `Storage:AssetsRoot`, `asset:` links → `/api/assets/{id}`, HtmlSanitizer, one transaction, paper saved as Draft). Exposed as `POST /api/admin/papers/import` (Admin). `POST /api/admin/papers/convert` (`AdminPaperConversionController`) takes the two PDFs + `audio1..5`, saves them under fixed names in a temp folder, runs `IPaperConverter` (`PythonPaperConverter`: `Converter:Python` / `Converter:Script`, argument list, timeout, reads the `--report` JSON; unset script → 503) one at a time, then imports the folder via `PackageFolder.Zip(fillMissing: false)`; `GET /api/admin/papers/{id}` is the review view with answer keys. The Docker API image carries Python + PyMuPDF and the converter (build context `converter` = setup/exam-package, whose `.dockerignore` keeps `sources/` out). The synthetic samples in `setup/exam-package/samples` are also the test fixtures; `python -I setup/exam-package/pack.py <folder> [--placeholders]` zips one. `setup/exam-package/pdf2package.py` (package `converter/`, PyMuPDF) turns a Cambridge A2 R&W or Listening question PDF + answer-key PDF (+ `--audio-dir` with one track per part for Listening; `split_listening.py <mp3> --parts 5` cuts a whole Cambridge recording at its end-of-part pauses, ffmpeg from PATH or `pip install --user imageio-ffmpeg`) into a draft folder (`paper.json`, `images/` saved from the embedded images, `REVIEW.md` with errors, checks and a per-question table); one reader per A2 part works on positioned lines, so the unit tests use invented lines laid out like the paper. Tests: `cd setup/exam-package && python -I -m pytest tests` (the real-sample test runs only when the PDFs are in `sources/`).
- `ExamPrep.Tests` — mirrors `src/`; `MySqlDatabaseFixture` + `A2ExamBuilder` for DB integration tests.

The schema has 25 tables in four groups: **content** (`exam_types → section_templates`, `test_papers → paper_parts → question_groups → questions → answer_keys`, `paper_mixes`, `assets`), **sessions** (`exams → exam_sections / candidates / exam_invigilators / exam_examiners`), **delivery** (`attempts`, `responses`, `annotations`, `manual_marks`), **monitoring** (`invigilator_actions`, `security_events`, `candidate_messages`), plus `users` (staff only) with `user_areas` (a manager's areas), `approval_requests` (VE-60 queue and log) and `site_settings` (centre name + logo, editable by a Centre manager).

Key modelling decisions:
- Exam types and their ordered sections are **data** (`section_templates`), so A2 (2 sections), B1 (3) and later IELTS share one engine. Never hard-code a section list.
- Candidate delivery API (`Api/Delivery`): `POST/GET /api/candidate/sections/{id}/attempt` start or resume through `AttemptClock` and return the clock plus saved answers; `PUT .../responses` upserts answers (409 when not running; 5 s grace). `AttemptExpiryWorker` sweeps every 5 s and submits expired attempts (TimeExpired) so offline candidates still end on time. There is deliberately no candidate submit (Cambridge: wait for time to expire or the invigilator to end the test). Listening: `POST .../audio` sets `AudioStartedAt` once; `audioPositionMs` comes from `AttemptClock.AudioPosition`; the browser (`exam/listening/useRecordingPlayer`) plays the part tracks back to back with no controls and resumes at the server position after a reload.
- Sections run strictly in order (Cambridge: each component ends before the next; Listening is last). `CandidateSectionsController` reports a later section as `Locked` and refuses its paper (403) until every earlier section has an attempt with status `Submitted` (candidate submit, time expired or invigilator End now).
- `question_groups.interaction_type` drives the candidate UI: `SingleChoice`, `ImageChoice`, `InlineChoice` (word picker over a gap), `InlineText` (typed gap), `DragDropMatch` (word cards), `Essay` (word counter). Inline gaps live in `body_html` as `{{q:19}}`.
- Listening audio is one track per part (`paper_parts.audio_asset_id`); the player chains them into one continuous recording, as Inspera does.
- Server-authoritative timer on `attempts`: change it only through `AttemptClock`, which recomputes `ends_at` from `started_at`, section duration, `paused_seconds`, `end_adjust_seconds` (signed; End now / End at / End in — relative so a later pause still moves the end), `planned_extra_seconds` + `incident_extra_seconds` (dropped when `disregard_extra_time`), capped by `candidates.parent_end_override_at`. Listening position = time since `audio_started_at` minus `audio_adjust_ms` (pauses and rewinds).
- `concurrency_stamp` is rotated automatically by `ExamPrepDbContext.SaveChanges` for every modified attempt; a write based on a stale read throws `DbUpdateConcurrencyException` — reload and retry, never force.
- `users.security_stamp` / `candidates.security_stamp` invalidate sign-in cookies (candidate login rotates it, so the previous computer is signed out). `exam_sections.start_announced_at` only drives the "started early" warning; it never blocks a candidate.
- **Paper shuffling (Victory 20/10, `Domain/Papers`):** `PaperShape.Differences` lists why two papers cannot be mixed (section, parts, groups, interaction, question numbers, recordings). `PaperMixer` (`POST /api/admin/paper-mixes`, Papers area) copies whole parts of two published sources into four published papers (`paper_mixes`; `test_papers.paper_mix_id / mix_version / mix_pattern` like "ABBAABA"); `PaperMixPlan.Patterns(parts, seed)` makes versions 1/2 and 3/4 opposites (a pair shares no part) and, from three parts on, every version mixes both sources. A section may deliver a mix (`exam_sections.paper_mix_id`, `test_paper_id` = version 1; `SectionPaper.PaperMixId` in the exam API); `PaperAssignment` gives the version of the candidate's seat by `SeatPattern` (2×2 tiles `[1 2 / 3 4]` over seat numbers run row by row with `exams.seats_per_row`; one row runs 1-2-3-4; no numeric `SeatNo` → place in the candidate list). The portal shows each candidate's version (`PaperVersion` on `CandidateView`, `MonitorRow`, `SectionResult`; `AttemptMarking.PaperTitle`), managers of exams list mixes at `GET /api/admin/exam-paper-mixes`, and `GET /api/staff/exams/{id}/room-plan` (people who run the room, `SlipsVisibleTo`) lays out seats with versions. `attempts.test_paper_id` is fixed when the section starts — delivery, audio, marking, results and the exam's assets read it, never `ExamSection.TestPaperId` — so a change of seat or computer keeps the paper. Mixed papers and their sources cannot be deleted. The demo mixes both A2 sources per section (`Demo:Second*Folder`, `Demo:SeatsPerRow` 4).
- Value rules are also MySQL CHECK constraints (durations > 0, extra percent 0–100, non-negative timer fields, scores within max); cross-row rules (unique question numbers per paper, paper matches the section template) are validated by the importer.
- **Safe Exam Browser (VE-28, `Api/Security`):** `exams.seb_config_key_hash` holds the Config Key of the exam's SEB settings (64 hex; empty = any browser). `SebActionFilter` (global MVC filter) refuses every candidate request of such an exam unless `X-SafeExamBrowser-ConfigKeyHash` = SHA-256(absolute URL + Config Key) (403 "Open this test in Safe Exam Browser."); sign-in checks it itself (`[SkipSebCheck]` on login/logout). nginx forwards `Host $http_host` because the hash covers the port. **Warnings (VE-29):** `SecurityEventRecorder` writes `security_events` for what the server observes — `InvalidSebKey` (request from outside SEB during a running attempt), `ConnectionLost` (heartbeat crossed the online window, found by `RoomBroadcaster`), `ClockSkew` (`X-Client-Time` on the heartbeat more than 2 min off), `StartedEarly` (attempts already started when the invigilator presses Announce start, `POST .../sections/{id}/announce-start`, which sets `exam_sections.start_announced_at` once) — without repeating an unresolved one; the monitor shows the count per candidate (`MonitorRow.Warnings`), `GET/POST .../sections/{id}/warnings[/{wid}/resolve]`.
- **Centre and paper editor:** `GET /api/site` + `/api/site/logo` are public (sign-in screens), `PUT /api/admin/site` and `POST /api/admin/site/logo` (PNG by signature, ≤ 1 MB) need the Centre area; the frontend reads it once (`ui/site.ts`, `VictoryLogo`). `AdminPaperEditorController` (VE-25) edits Draft papers only (409 otherwise): title, part title/passage/recording, group instructions/text/card texts (`PaperHtml.GapProblems` for `{{q:n}}`), question wording/option texts/answers/points/min words, option pictures (`.../questions/{n}/options/{key}/image`) and pictures for the HTML (`.../images` answers the `/api/assets/{id}` URL), with the importer's rules; option and card keys never change. `POST /api/admin/papers/blank` imports `PaperSkeletons` (A2 R&W and Listening layouts; texts start with `[to write`, placeholder PNG/WAV) and publishing refuses a paper that still has a marker or a placeholder asset (400 with the places).
- **Two-admin approval (VE-60, Victory 16/10):** deleting a paper, exam or candidate and changing a staff account (activate/deactivate, role, areas, password reset, a third admin) never happen at once: the endpoint answers 202 with an `ApprovalView` and files an `approval_requests` row (`Api/Approvals`: `ApprovalService`, `ApprovalActions` checks each kind when asked and again when approved, `ApprovalsController` at `/api/staff/approvals`). An admin other than the requester approves (the action runs in the same save; Failed with the reason if it became impossible) or rejects with a note; the requester may cancel. Nobody decides their own request (also a CHECK constraint); `status` is a concurrency token; a decided request drops the password hash it carried. Managers file requests only in their areas and never delete directly. With a single active admin, the second admin is created directly. Names and emails of staff change at once.
- Auto-marking uses `answer_keys` (several rows = accepted alternatives). Writing has no key: examiners mark it in `manual_marks`. `Domain/Marking/AnswerMatcher` compares choices by option key and typed answers after normalising case (unless `is_case_sensitive`), spaces, curly apostrophes and a final full stop — never spelling. `Infrastructure/Marking/AttemptMarker` (run by `AttemptExpiryWorker` after the time-up sweep) marks Submitted + NotGraded attempts; papers with an Essay stay `NeedsManualMarking`. Staff session endpoints filter through `Exams/ExamAccess` (`VisibleTo`, `SlipsVisibleTo`, `MonitorableBy`, `ResultsVisibleTo`, `MarkableBy`): managers of exams or candidates reach every session, invigilators and examiners only those they are assigned to (404 otherwise); examiners get the session without its PIN and invigilator password. Admin APIs (`Api/Admin`, papers, users; managers in their areas) create sessions with one published paper per section, enter candidates (username `Domain/Candidates/CandidateUsername`, passwords via `CandidateCredentials`, re-printable slips) and staff accounts (administrators only; `GET /api/admin/exam-papers` and `/assignable-staff` let an exams manager pick papers and staff). Invigilator actions (`Monitoring/InvigilatorActionRules` over `AttemptClock`) apply only where Inspera allows and report the rest as skipped; each is logged in `invigilator_actions`. `GET /api/staff/exams/{id}/results` (score table) is for admins (every session) and examiners (theirs); `GET /api/staff/attempts/{id}/marking` (the candidate's answers with the key) is for assigned examiners only and answers 409 until the section is Submitted; `POST /api/staff/attempts/{id}/writing-marks` (assigned examiner) records a Writing mark (`manual_marks`) and, once every Writing question is marked, sets the score to automatic + Writing and the status to Final. Candidates never see marks.

## Exam-room behaviour to reproduce (from the refs)

- **Candidate login:** printed username (first 5 letters of family name + first initial + candidate number) and password, then the session PIN the invigilator reads out (`exams.session_pin`). `exams.invigilator_password` exits the lockdown browser or moves a candidate to another computer.
- **Invigilator operations** happen at section level, only on candidates who are online and in progress: pause/resume (single, multi-select, whole room), incident extra time, Edit End Time (*End now / End at / End in*; End now offers "Disregard extra time" for candidates with extra time). End now at section level is irreversible.
- **Listening incident:** two separate actions — rewind audio by N minutes (only while the candidate is not paused, at most the minutes already played), then add the same minutes as incident extra time.
- **Ended at parent level by mistake:** restore with Edit End Time → "Use test end time" (`candidates.parent_end_override_at` back to null).
- **Offline candidates** cannot be paused; their clock keeps running and the invigilator adds incident time when they log back in.
- **SEB:** the server validates the Safe Exam Browser config key; only server-observable warnings are real (`security_events`).
