## Commands

Run from `src/backend` unless noted. Requires .NET SDK 10 (pinned in `global.json`) and Docker Desktop.

```bash
# Start MySQL only (from repo root). docker/.env holds the passwords and is git-ignored; copy docker/.env.example first.
docker compose -f docker/docker-compose.yml --env-file docker/.env up -d mysql
# Or the whole DEMO system (MySQL + API + nginx serving the built frontend and proxying /api) at http://localhost:8080.
# The api container runs as Development (demo exams, sample accounts with public passwords: never a real exam), migrates on
# start (Database:MigrateOnStart), runs as the non-root user `app` and shares the MySQL volume and
# src/backend/src/ExamPrep.Api/App_Data with `dotnet run`. MySQL is published on 127.0.0.1 only.
docker compose -f docker/docker-compose.yml --env-file docker/.env up -d --build
# A real exam: the production override, always under its own project name (Production, no demo, HTTPS on 443 from the
# git-ignored docker/certs/server.crt + server.key, first admin from BOOTSTRAP_ADMIN_* required, uploads in the api-data volume).
docker compose -p examprep-prod -f docker/docker-compose.yml -f docker/docker-compose.prod.yml --env-file docker/.env up -d --build

# Connection string for the API (Development reads user-secrets)
dotnet user-secrets set "ConnectionStrings:ExamPrep" "server=localhost;port=3306;database=examprep;user=examprep;password=<MYSQL_PASSWORD>" --project src/ExamPrep.Api

# Build / run (health check at /health)
dotnet build
ASPNETCORE_ENVIRONMENT=Development dotnet run --project src/ExamPrep.Api

# Migrations (design-time factory reads ConnectionStrings__ExamPrep from the environment)
dotnet ef migrations add <Name> -p src/ExamPrep.Infrastructure -s src/ExamPrep.Api -o Persistence/Migrations
ConnectionStrings__ExamPrep="<conn>" dotnet ef database update -p src/ExamPrep.Infrastructure -s src/ExamPrep.Api

# Tests (Microsoft.Testing.Platform runner, xUnit v3). DB tests need a server-level root connection
# and are reported as skipped without it; each run creates and drops its own examprep_test_* database
# (migrations run one at a time on an unpooled connection: EF's MySQL migration lock is server-wide).
EXAMPREP_TEST_MYSQL="server=localhost;port=3306;user=root;password=<MYSQL_ROOT_PASSWORD>" dotnet test
dotnet test --filter-method "*SnakeCase*"      # single test / pattern
```

## Backend architecture (`src/backend`)

- `ExamPrep.Domain` — entities (one class per file), enums, and domain logic: `Delivery/AttemptClock` (all timer and audio rules; throws `Common/DomainRuleException` for operations not allowed in the current state). No EF dependency.
- `ExamPrep.Infrastructure` — `DependencyInjection.WithPoolSize` adds `Maximum Pool Size=250` unless the connection string sets one (MySql.Data's blocking async calls ran the default 100 out at 200 candidates; MySQL runs with `--max-connections=300`, Program.cs raises the minimum threads to 200); `Persistence/ExamPrepDbContext`, one `IEntityTypeConfiguration` per entity in `Persistence/Configurations`, migrations, `SeedData` (exam types, section templates, default branding "Victory"). `ModelConventions` stores every enum as `varchar(32)` text and every `DateTime` as UTC; `SnakeCaseNaming` lower-snake-cases all tables and columns. Provider is Oracle's `MySql.EntityFrameworkCore` 10 (`UseMySQL`), because Pomelo has no EF Core 10 release.
- `ExamPrep.Api` — ASP.NET Core host; `AddInfrastructure` fails fast if the connection string is missing. `Auth/` has two separate cookie schemes sharing `ApiCookieOptions` (HttpOnly, SameSite=Strict, 401/403 instead of redirects): **Staff** (`victory.staff`, roles Admin / Manager / Examiner / Invigilator, an `area` claim per manager area; policies `Staff`, `Admin`, `Papers`/`Exams`/`Candidates`/`Centre` (admin or a manager of that area), `CandidateList`, `Results` (administrators only), `Examiner` (the anonymous Writing scripts); first admin from `Bootstrap:AdminUsername`/`AdminPassword`) and **Candidate** (`victory.candidate`; login → `pin_verified=False`, `POST /api/candidate/auth/pin` re-issues it with `True`; policy `CandidateExam` requires the PIN). Both re-check `security_stamp` on every request; candidate login rotates it. Candidates can sign in only while `exams.status = Active`. `LoginThrottle` locks an account for 5 minutes after 10 wrong passwords (or 10 wrong PINs for a candidate), counted per account id because MySQL matches usernames ignoring case and accents. Data Protection keys (cookies, re-printable candidate passwords) persist in `App_Data/keys` (`DataProtection:KeysPath`). Every response carries nosniff / X-Frame-Options DENY / no-referrer / CSP `default-src 'none'`; outside Development a ProblemDetails exception handler and HSTS.
- `ExamPrep.Infrastructure/Content` — exam packages (one .zip per paper: `paper.json` + images/ + audio/, spec in `setup/exam-package/FORMAT.md`): `PaperPackageReader` (strict JSON, names confined to the package, size limits) → `PaperPackageValidator` (template part count, numbering 1..N, per-interaction rules; returns every error as an admin-readable sentence) → `PaperPackageImporter` (SHA-256 content-addressed `IAssetStorage` under `Storage:AssetsRoot`, `asset:` links → `/api/assets/{id}`, HtmlSanitizer, one transaction, paper saved as Draft). Exposed as `POST /api/admin/papers/import` (Admin). `POST /api/admin/papers/convert` (`AdminPaperConversionController`) takes the question PDF, the answer key (optional: B1 Writing has none, the script reports it missing for the rest) + `audio1..5`, saves them under fixed names in a temp folder, runs `IPaperConverter` (`PythonPaperConverter`: `Converter:Python` / `Converter:Script`, argument list, timeout, reads the `--report` JSON; unset script → 503) one at a time, then imports the folder via `PackageFolder.Zip(fillMissing: false)`; `GET /api/admin/papers/{id}` is the review view with answer keys. The Docker API image carries Python + PyMuPDF and the converter (build context `converter` = setup/exam-package, whose `.dockerignore` keeps `sources/` out). The synthetic samples in `setup/exam-package/samples` are also the test fixtures; `python -I setup/exam-package/pack.py <folder> [--placeholders]` zips one. `setup/exam-package/pdf2package.py` (package `converter/`, PyMuPDF) turns a Cambridge question PDF + answer-key PDF — A2 Key R&W / Listening or B1 Preliminary Reading / Writing / Listening, told apart by the cover (`component()`) — (+ `--audio-dir` with one track per part for Listening; `split_listening.py <mp3> --parts 5` (B1: 4) cuts a whole Cambridge recording at its end-of-part pauses (A2: 10 s + "Now look at Part n" + 5 s; B1: every 10 s pause except the one before the transfer time), ffmpeg from PATH or `pip install --user imageio-ffmpeg`) into a draft folder (`paper.json`, `images/` saved from the embedded images, `REVIEW.md` with errors, checks and a per-question table); one reader per part (`a2_reading_writing`, `a2_listening`, `b1_reading`, `b1_writing`, `b1_listening`) works on positioned lines, `answer_key.expand_optional` turns `(a/the) waterfall(s)` into every accepted form, so the unit tests use invented lines laid out like the paper. Tests: `cd setup/exam-package && python -I -m pytest tests` (the real-sample test runs only when the PDFs are in `sources/`).
- `ExamPrep.Tests` — mirrors `src/`; `MySqlDatabaseFixture` + `A2ExamBuilder` for DB integration tests.

The schema has 28 tables in four groups: **content** (`exam_types → section_templates`, `test_papers → paper_parts → question_groups → questions → answer_keys`, `answer_corrections` (audit of answer-key corrections), `paper_mixes → paper_mix_sources`, `assets`), **sessions** (`exams → exam_sections / candidates / exam_invigilators / exam_examiners / exam_candidate_managers`), **delivery** (`attempts`, `responses`, `annotations`, `manual_marks`), **monitoring** (`invigilator_actions`, `security_events`, `candidate_messages`), plus `users` (staff only) with `user_areas` (a manager's areas), `approval_requests` (VE-60 queue and log) and `site_settings` (centre name + logo, editable by a Centre manager).

Key modelling decisions:
- Exam types and their ordered sections are **data** (`section_templates`), so A2 (2 sections), B1 (3) and later IELTS share one engine. Never hard-code a section list.
- Candidate delivery API (`Api/Delivery`): `POST/GET /api/candidate/sections/{id}/attempt` start or resume through `AttemptClock` and return the clock plus saved answers; `PUT .../responses` upserts answers (409 when not running, with `code` `paused`, `finished` or `busy`; `AttemptExpiry.AutosaveGrace` of 5 s on every path that submits on time: sweep, heartbeat, GET attempt, save). `AttemptExpiryWorker` sweeps every 5 s and submits expired attempts (TimeExpired) so offline candidates still end on time. There is deliberately no candidate submit (Cambridge: wait for time to expire or the invigilator to end the test). The paper, its pictures and its recordings are served only while the candidate has a running attempt at the section. Listening: `POST .../audio` sets `AudioStartedAt` once; `audioPositionMs` comes from `AttemptClock.AudioPosition`; the browser (`exam/listening/useRecordingPlayer`) plays the part tracks back to back with no controls, resumes at the server position after a reload, restarts by itself after a pause and again after a rewind past the end of the recording, and gives up on a track that does not load within 10 s so later rewinds still work.
- Sections run strictly in order (Cambridge: each component ends before the next; Listening is last). `CandidateSectionsController` reports a later section as `Locked` and refuses its paper (403) until every earlier section has an attempt with status `Submitted` (time expired, invigilator End now or End all).
- `question_groups.interaction_type` drives the candidate UI: `SingleChoice`, `ImageChoice`, `InlineChoice` (word picker over a gap), `InlineText` (typed gap), `DragDropMatch` (cards dragged onto slots), `Essay` (word counter). Inline gaps live in `body_html` as `{{q:19}}`. `DragDropMatch` has three layouts read from the data (`exam/listening/DragDropMatch.tsx`, VE-34): rows of short labels (A2 Listening 5), people with a picture and a description when questions have `stimulus_html` (B1 Reading 2), and gaps in `body_html` (B1 Reading 4, no labels needed); cards may carry a bold `title`, and `question_groups.items_heading` / `pool_heading` head the two columns. The self-written `samples/b1-pfs-reading`, `samples/b1-pfs-writing` and `samples/b1-pfs-listening` are the B1 fixtures. Paging (`exam/paperLogic.buildPages`): a part goes one question per page when `paper_parts.question_per_page` is set (package `questionPerPage`; B1 Listening Part 2, B1 Writing Part 2) or when every question carries its own pictures (A2 Reading Part 1, Listening Part 1); otherwise the part is one page.
- Listening audio is one track per part (`paper_parts.audio_asset_id`); the player chains them into one continuous recording, as Inspera does.
- Server-authoritative timer on `attempts`: change it only through `AttemptClock`, which recomputes `ends_at` from `started_at`, section duration, `paused_seconds`, `end_adjust_seconds` (signed; End now / End at / End in — relative so a later pause still moves the end), `planned_extra_seconds` + `incident_extra_seconds` (dropped when `disregard_extra_time`), capped by `candidates.parent_end_override_at`. Listening position = time since `audio_started_at` minus `audio_adjust_ms` (pauses and rewinds).
- `concurrency_stamp` is rotated automatically by `ExamPrepDbContext.SaveChanges` for every modified attempt; a write based on a stale read throws `DbUpdateConcurrencyException` — reload and retry, never force.
- `users.security_stamp` / `candidates.security_stamp` invalidate sign-in cookies (candidate login rotates it, so the previous computer is signed out). `exam_sections.start_announced_at` only drives the "started early" warning; it never blocks a candidate.
- **Paper shuffling (Victory 20/10, widened 29/10 VE-70, `Domain/Papers`):** `PaperShape.Differences` lists why two papers cannot be mixed (section, parts, groups, interaction, question numbers, recordings). `PaperMixer` (`POST /api/admin/paper-mixes` with `sourcePaperIds` 2–6 in letter order and `versionCount`, Papers area, own papers only) copies whole parts of the published sources into K published papers, 4 ≤ K ≤ `PaperMixPlan.MaxVersions` = min(3N, N^parts) (`paper_mixes.version_count`, sources in `paper_mix_sources` by position A, B, C…; `test_papers.paper_mix_id / mix_version / mix_pattern` like "ACBBA"). `PaperMixPlan.Patterns(sources, parts, versions, seed)` splits the versions into `Families` of even size (at most N each); a family turns one pattern round the sources (version j takes part p from source (b[p] + j) mod N), so two versions of one family share no part; families start from different patterns that mix sources (the whole-source pattern only when the parts run out). Two sources and four versions give the old pairs 1/2, 3/4. A section may deliver a mix (`exam_sections.paper_mix_id`, `test_paper_id` = version 1; `SectionPaper.PaperMixId` in the exam API); `PaperAssignment` gives the version of the candidate's seat by `SeatPattern.VersionFor(seat, seatsPerRow, MixShape)`: each row takes one family in turn and its seats run through it (side by side: no shared part; 2 sources × 4 versions = 2×2 tiles `[1 2 / 3 4]`), or (column + 2·row) mod K when there is one family or a family of one; all eight neighbours always differ; one row runs 1…K; no numeric `SeatNo` → the lowest number nobody typed, in candidate-list order (without typed seats, the place in the list). The portal shows each candidate's version per mixed section (`PaperVersions` on `CandidateView` and `RoomSeat`; `PaperVersion` on `MonitorRow`, `SectionResult`; `AttemptMarking.PaperTitle`), managers of exams list mixes at `GET /api/admin/exam-paper-mixes`, and `GET /api/staff/exams/{id}/room-plan` (people who run the room, `SlipsVisibleTo`) lays out seats with versions. `attempts.test_paper_id` is fixed when the section starts — delivery, audio, marking, results and the exam's assets read it, never `ExamSection.TestPaperId` — so a change of seat or computer keeps the paper. Mixed papers and their sources cannot be deleted. The demo mixes both A2 sources per section (`Demo:Second*Folder`, `Demo:SeatsPerRow` 4).
- **Schema hardening (27/10, migration `HardenSchema`):** `EnumCheckConstraints` gives every enum column a CHECK with exactly its enum's names (generated from the model, so a new enum value needs only a migration); `CK_attempts_state` ties the status to its timestamps (started_at unless NotStarted, paused_at exactly when Paused, submitted_at + submit_reason exactly when Submitted, graded only when Submitted), `CK_attempts_score`, `CK_exams_session_pin` (4–8 digits), `CK_exams_seb_config_key` (64 lower-case hex), `CK_approval_requests_decision` (pending exactly when undecided), `CK_site_settings_single_row`. Attempts are exam records: `attempts.candidate_id` and `exam_section_id` are RESTRICT, so the database refuses to delete a candidate, section or exam with work in it; only the demo reset deletes attempts, explicitly.
- Value rules are also MySQL CHECK constraints (durations > 0, extra percent 0–100, non-negative timer fields, scores within max); cross-row rules (unique question numbers per paper, paper matches the section template) are validated by the importer.

## Exam-room behaviour to reproduce (from the refs)

- **Candidate login:** printed username (first 5 letters of family name + first initial + candidate number; a family name shorter than 5 letters takes more letters of the given name, always 6 letters when the names allow) and password, then the session PIN the invigilator reads out (`exams.session_pin`). The screens follow the Exam Day Booklet 2026 candidate instructions word for word (`screens/SignInScreens.tsx`, checked 27/10): Login → Next → "PIN code" + "Unlock and Select" → Next → candidate icon (top right) to check the name → readiness check (Confirm, forward arrow; our own text and a test sound, kept per exam and candidate in localStorage) → per component its instructions, "I confirm", "Start (name)" → back to the dashboard when it closes → Exit after the last. The clock shows m:ss from 5 minutes left; Listening has a volume control; the bell also hides the test; no notepad with large text or a screen 1366 px wide or less. Planned extra time cannot change once the candidate has started (incident time is for the day). Monitor wording as in Inspera: Never started, Minutes remaining, Candidate started; Resume has no reason; rewind takes optional details. `exams.invigilator_password` exits the lockdown browser or moves a candidate to another computer.
- **Invigilator operations** happen at section level, only on candidates who are online and in progress: pause/resume (single, multi-select, whole room), incident extra time, Edit End Time (*End now / End at / End in*; End now offers "Disregard extra time" for candidates with extra time). End now at section level is irreversible and only ever brings the end forward.
- **Listening incident:** two separate actions — rewind audio by N minutes (only while the candidate is not paused, at most the minutes already played), then add the same minutes as incident extra time.
- **Ended at parent level by mistake:** restore with "Use test end time" for the whole test on the exam page (`POST .../use-test-end-time`, two-click confirm; `candidates.parent_end_override_at` back to null even after the sweep has submitted the running section, which stays submitted); the parent-level end itself is "End the whole test" on the exam page (`POST .../end-all`, two-click confirm).
- **Offline candidates** cannot be paused; their clock keeps running and the invigilator adds incident time when they log back in.
- **SEB:** the server validates the Safe Exam Browser config key; only server-observable warnings are real (`security_events`).
